  ## 4. start / stop / delete / recheck
  
  - The only actions are `startAction`, `stopAction`, `recheckAction`, `deleteAction` and so on (torrentscontroller.h). There is no `pause` or `resume`. An unknown action gives 404 (apicontroller.cpp: `if (!QMetaObject::invokeMethod(...)) throw APIError(APIErrorType::NotFound);`).
  - POST is enforced (webapplication.h `m_allowedMethod`): `{{u"torrents"_s, u"start"_s}, Http::METHOD_POST}`, `stop`, `delete`, `recheck`, `add` and so on. A wrong method gives 405 (`if (*allowedMethodIter != m_request.method) throw MethodNotAllowedHTTPError();`).
  - `start`: `requireParams({u"hashes"_s}); ... split(u'|'); applyToTorrents(idStrings, [](...){ torrent->start(); });`
  - `delete`: `requireParams({u"hashes"_s, u"deleteFiles"_s});`, and `deleteFiles` is parsed with parseBool (so `true`/`false`; anything else means keep content). Missing params give 400 (`BadParams` maps to `BadRequestHTTPError`).
  - **Unknown hashes are silently ignored.**
    ```cpp
    if ((idList.size() == 1) && (idList[0] == u"all")) { for (... torrents()) func(torrent); }
    else { ... BitTorrent::Session::instance()->getTorrent(hash); if (torrent) func(torrent); }
    ```

  - A malformed hash (wrong length or non-hex) becomes an invalid digest. digest32.h: `if (digestString.size() != (length() * 2)) ...`. The lookup finds nothing and it is ignored.

  ## 7. Settings that matter for "never download or modify"
  
  - **`add_stopped_enabled` / `torrent_stop_condition`:** the global defaults. They apply when `stopped` or `stopCondition` is absent or unparseable (`value_or(isAddTorrentStopped())`, `value_or(torrentStopCondition())`).
  - **`incomplete_files_ext` (`.!qB`):**
    - At add time, the file searcher renames missing files to `name.!qB` (filesearcher.cpp: `else if (forceAppendExt) fileName = incompleteFilename;`). It also adopts an existing `name.!qB` if present.
    - After a recheck, the trigger calls `manageActualFilePaths()`, which runs even for stopped torrents. It renames on disk every file with size > 0 that is not complete: `makeActualPath`: `if (m_session->isAppendExtensionEnabled() && (fileSize(index) > 0) && !m_completedFiles.at(index)) actualPath += QB_EXT;` then `doRenameFile` then `rename_file`.
    - So a partial or mismatched reseed will rename the user's files to `.!qB`.
    - Completed files are marked via `file_completed_alert`, which libtorrent posts during checking (`on_piece_hashed` calls `we_have(piece)`, which posts `file_completed_alert`).
  - **`temp_path_enabled` / downloadPath:**
    - After a check, `adjustStorageLocation()` moves storage: `targetPath = ((isFinished() || m_hasFinishedStatus || downloadPath.isEmpty()) ? savePath() : downloadPath); ... moveStorage(...)`. An incomplete torrent with a download path set gets its files moved.
    - The file searcher also switches the save path to downloadPath if nothing is found in savePath.
    - Pass `useDownloadPath=false`.
  - **`auto_tmm_enabled`:** decides whether the default autoTMM ignores `savepath`. Pass `autoTMM=false`.
  - **`excluded_file_names_enabled` / `excluded_file_names`:** `applyFilenameFilter` sets matching files to Ignored at add time. This changes `size`/`amount_left`. With `use_unwanted_folder`, Ignored files are moved into the `.unwanted` subfolder by `makeActualPath`/`manageActualFilePaths`.
  - **`preallocate_all`:** `p.storage_mode = isPreallocationEnabled() ? lt::storage_mode_allocate : lt::storage_mode_sparse;`. I did not verify whether a check alone triggers allocation of missing files.
  - **libtorrent storage `initialize()`** runs on every check. It creates zero-length files and symlinks that don't exist (storage_utils.cpp `initialize_storage`: "if the file is empty and doesn't already exist, create it"). These are small disk writes even on a pure check.
  - **`merge_trackers`:** on duplicate add of a non-private torrent, trackers and web seeds are merged into the existing torrent (quoted in section 1).
  - **`add_trackers_enabled` / `add_trackers_from_url_enabled`:** extra trackers are appended on add unless the torrent is private (`if (isAddTrackersEnabled() && !(hasMetadata && p.ti->priv()))`).
  - **`add_to_top_of_queue` / `addToTopOfQueue`:** only affects `queue_position_top()`.
  - **`queueing_enabled` / `max_active_downloads`:** decide whether auto-manage would resume the torrent in the no-files window from section 2.
  - **`max_active_checking_torrents`:** `active_checking`, default 1.
  - **`export_dir`:** writes a .torrent copy on add (createTorrent `exportTorrentFile`). The finished export dir is written on finish.
  - **A successful check of a complete, non-skip torrent counts as "finished".** libtorrent's `finished()` posts `torrent_finished_alert`. qBittorrent then sets `m_hasFinishedStatus = true` and `m_session->handleTorrentFinished(this)`, which emits `torrentFinished`, runs the finished-torrent export and runs `processTorrentShareLimits`.   - **`skip_checking=true`:** sets `lt::torrent_flags::seed_mode` and `hasFinishedStatus = true`. libtorrent then assumes it has every piece without checking, so avoid it for verification.
  - **`torrent_content_remove_option`:** controls what `deleteFiles=true` does, move to trash or delete.
